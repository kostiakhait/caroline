# mcp-windows-chain

MCP-сервер, который выполняет **целую линейную последовательность** input/wait/process-шагов
за один вызов инструмента — вместо одного round-trip к LLM на каждый клик/скриншот. Появился
как ответ на то, что GUI-автоматизация UE5 Blueprint-редактора через `mouse`/`keyboard`/
`screenshot`/`window-screenshot`/`inspect` оказалась медленной и дорогой по токенам. Дизайн
зафиксирован в `../CHAIN_DESIGN.md`.

Node/TypeScript слой резолвит имена клавиш в VK-коды (как `window-keyboard`) и пишет шаги во
временный JSON-файл; нативный `chain.exe` (C#/.NET) выполняет их один за другим сам, без
обращений к LLM между шагами.

## Инструмент

- `run_chain(steps)` — прогоняет массив шагов. Каждый шаг — объект с полем `op`:
  - **Ввод:** `move`, `click`, `mouse_down`/`mouse_up`, `drag`, `key`, `type`, `scroll` — **у
    каждого из этих семи есть и оконный (`hwnd`), и глобальный вариант**, переключение просто по
    наличию `hwnd` в шаге. Симметрия намеренная: даже для GPU-рендеренных UI (UE5 Slate и т.п.),
    которые понимают только глобальный ввод, всё равно нужна выгода от прогона всей
    последовательности за один вызов, а не только для стандартных Win32-контролов.
  - **Ожидания:** `sleep`, `wait_window` (по природе глобальный — ищет по всем окнам),
    `wait_pixel` (оконный вариант читает из PrintWindow-захвата самого окна — работает даже для
    перекрытого/неактивного окна; глобальный — с живого экрана), `wait_idle` (оконный или по
    региону экрана)
  - **Процессы:** `launch`, `kill`, `restart`
  - **Безопасность:** `checkpoint` — намеренная пауза (`status:"paused"`, не ошибка) перед
    рискованным шагом, со скриншотом (по `hwnd` или full-screen); возобновление — новый вызов
    `run_chain` против уже изменившегося состояния GUI, без токенов на статус/сессию.

  Шаги с `hwnd` идут через `PostMessage` (без кражи фокуса, как `window-mouse`/`window-keyboard`)
  — работает для стандартных Win32-контролов. Шаги без `hwnd` идут через реальный
  `SendInput`/`SetCursorPos` (крадёт фокус, как `mouse`/`keyboard`) — нужен для
  GPU-рендеренных UI, которые PostMessage игнорируют целиком.

  `launch`/`wait_window` с полем `as` привязывают PID к имени; later-шаги ссылаются на него как
  `"$name"` в `hwnd`/`pid`.

  Ответ — не просто ok/fail, а `{status, completedSteps, failedAt:{index,op,reason}|null,
  elapsedMs, screenshot}` — вызывающий точно знает, на каком шаге и почему цепочка остановилась.

**Сознательно не реализовано в v1** (см. `CHAIN_DESIGN.md`): ветвления, циклы, произвольные
выражения — язык шагов специально "глупый" и линейный, решения остаются за LLM. `wait_element`
через UI Automation API — открытый вопрос для следующей версии.

## Сборка

Требуется .NET 8 SDK (`dotnet --version`).

```bash
npm install
npm run build
```

## Подключение к Claude Code

Добавить в `.mcp.json` проекта:

```json
{
  "mcpServers": {
    "windows-chain": {
      "command": "node",
      "args": ["D:/REPO/silmarillion/MCP/chain/dist/index.js"]
    }
  }
}
```
